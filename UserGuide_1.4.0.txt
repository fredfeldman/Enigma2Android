## 1. Quick Start / First Launch

When you open E2Android for the first time the Setup screen appears.

| Field | Description |
| --- | --- |
| Device Name | A label for this receiver (e.g. "Living Room") |
| Host / IP | IP address or hostname of your receiver (e.g. `192.168.1.100` or `dreambox.local`) |
| Port | OpenWebif HTTP port. Default is `80`. Some configurations use `8080`. |
| Username | Leave blank if OpenWebif has no auth; otherwise enter the configured username. |
| Password | Leave blank if OpenWebif has no auth. |
| MAC Address | 12 hex digits (e.g. `AA:BB:CC:DD:EE:FF`). Only needed for Wake-on-LAN; can be left blank. |
| Use HTTPS | Tick if your OpenWebif is on HTTPS. |

Tap **CONNECT**. The app will fetch the bouquet list from your receiver and display the channel screen.

---

## 2. Adding & Switching Devices

You can store any number of receiver profiles.

- **Add a new device** — Channel screen → toolbar → *Switch Device* icon → *+ Add Device*. Fill in the same fields as first launch and tap **SAVE**.
- **Switch the active device** — Channel screen → toolbar → *Switch Device* icon. Tap any entry to make it the active receiver. The channel list immediately refreshes.
- **Edit / delete a device** — Long-press (or swipe) an entry in the device list to reveal Edit and Delete options.
- **Back** — Tap the ← arrow (top-left) or use the Android back gesture to return without changing the device.

---

## 3. Channel Screen

**Layout**

- **Left panel** — Bouquet list (e.g. "Favourites", "Sky UK", "BBC HD")
- **Right panel** — Channel list for the selected bouquet

**Channels**

- Each channel row shows: picon logo, channel name, current programme title, a progress bar for the current programme, and the *Next* programme.
- **Tap** a channel — by default opens the full-screen player. The behaviour is configurable in Settings (see [§12](#12-settings) — *Action when tapping a channel*: stream / zap only / both).
- **Long-press** a channel for a context menu: Show EPG, Set Timer, Add to Favourites.

**Toolbar buttons** (top-right)

| Icon | Action |
| --- | --- |
| 🔍 | Filter / search channel names (300 ms debounce) |
| ★ | Toggle favourite for the selected channel |
| 📷 | Receiver screenshot |
| ⏰ | Timers |
| ⏱ | AutoTimers |
| 📺 | EPG grid |
| ⋮ | Overflow — Switch Device, Recordings, Playlists, Settings |

## 4. Playing Live TV

Tap a channel (or use *Zap and stream* — see Settings). The player opens full-screen.

**OSD (On-Screen Display)** — Tap the video to show / hide; auto-hides after 5 s.

The OSD shows: channel name + current programme title, Play/Pause, Previous channel ◀◀, Next channel ▶▶, audio track selector, subtitle / CC selector, aspect-ratio cycle, sleep timer, and × Stop (top-left, always visible).

**Changing channel from the player** — Use ◀◀ / ▶▶ to step through channels in the current bouquet without returning to the channel screen. Whether this also tunes the receiver is controlled by the *Zap receiver when changing channel in player* setting (default on).

---

## 5. EPG (Electronic Programme Guide)

Access: Channel screen toolbar → EPG icon.

**Layout**

- **Left column** — Pinned channel names (aligned with their EPG rows)
- **Main area** — Horizontal scrolling programme grid (rows = channels, columns = time slots)
- **Top ruler** — Time axis; scroll left / right to move through time

**Navigation**

- Swipe left / right — scroll through time
- Swipe up / down — scroll through channels (channel names scroll in sync)
- Tap a programme — selects it (shows title + description overlay)
- Double-tap — play the channel immediately
- Long-press — set a timer for that programme

---

## 6. EPG Search

Access: EPG screen → search icon, or channel screen overflow → *EPG Search*.

1. Type a programme title (or partial title). Search runs after 3+ characters with 400 ms debounce.
2. Results show channel name (resolved from sref), date/time and title.
3. Tap a result to highlight it in the EPG grid or open a detail view to start a timer.

---

## 7. Recordings

Access: Channel screen overflow → *Recordings*. Pull down to refresh.

- **Play** — Tap a recording then **PLAY**. A seek bar appears in the OSD; ⏪ 15s / ⏩ 15s buttons jump in 15-second steps.
- **Resume** — If auto-resume is enabled in Settings the player offers to resume from the last watched position.
- **Delete** — Long-press a recording → *Delete*. Confirms, then calls `api/movie/delete` and removes the entry.
- **Add to Playlist** — Long-press → *Add to Playlist*.

## 8. Player Controls (detail)

The same player is used for live TV and recordings.

| Control | Action |
| --- | --- |
| Tap video | Show / hide OSD (auto-hides after 5 s) |
| × button | Stop and exit (top-left, always visible) |
| ▶ / ⏸ | Play / Pause |
| ◀◀ / ▶▶ (live TV) | Previous / Next channel in current bouquet |
| ⏪ 15s / ⏩ 15s (recordings) | Rewind / Fast-forward 15 s |
| Seek bar (recordings) | Drag to any position |

**Audio tracks** — Tap the audio-track icon to choose between e.g. English AC3, English stereo, German.

**Subtitles / CC** — Tap the CC icon for available subtitle tracks; choose *Off* to disable.

**Aspect ratio** — Cycles FIT → FILL → ZOOM → 16:9 → 4:3.

**Sleep timer** — 15 / 30 / 60 min / Cancel. A countdown badge appears while active; the player stops when it expires.

## 9. Timers

Access: Channel screen toolbar → Timers icon. Pull down to refresh.

Each row shows programme title, channel name, start / end date/time, and state (waiting / recording / completed / failed).

- **Delete** — Tap the trash icon. Confirms, then removes the timer from the receiver via `api/timerdelete`.
- **Create** — From the EPG grid (long-press a programme) or the channel list (long-press a channel).

## 10. AutoTimers

Manage Enigma2 AutoTimer rules from the app. Requires the AutoTimer plugin to be installed on the receiver.

Access: Channel screen toolbar → AutoTimers icon (⏱).

Each row shows the rule's name, match text, services, time window and enabled state.

- **Toggle** — Use the row switch to enable / disable a rule in place.
- **Edit** — Tap a rule to open the edit dialog: name, match text, time window, *zap only* flag.
- **Delete** — Long-press → confirm.

Backed by `autotimer`, `autotimer/edit` and `autotimer/remove` endpoints. AutoTimer XML is parsed with `XmlPullParser` so no extra setup is needed on the receiver.

## 11. Playlists

Access: Channel screen overflow → *Playlists*. Playlists are stored locally on the tablet.

- **Create** — + (FAB) → name → **CREATE**.
- **Add recordings** — Open the playlist → *Add Recording* → pick from the receiver's recordings.
- **Play** — Open the playlist → tap the first item or **PLAY ALL**. Items play sequentially.
- **Reorder** — Long-press an entry and drag.
- **Rename / Delete** — Long-press the playlist name in the manager.
- **HDD / NAS browser** — Playlists → *Browse Files*. Browse and play files directly from receiver storage.

## 12. Settings

Access: Channel screen overflow → *Settings*.

### Connection
Host, port, HTTPS, username, password — applies to the active device profile.

### Display
- **Hide Bouquets** — Tick bouquets to omit from the channel list.
- **Edit bouquets** *(new in 1.0.5)* — opens the Bouquet Editor. See [§15](#15-bouquet-editor).
- **Night mode** — Dark (default) or light theme.

### Playback
- **Auto-resume** — Offer to resume recordings from the last watched position.
- **Action when tapping a channel** — choose:
  - *Stream in player* — default, original behaviour.
  - *Zap receiver only* — sends `api/zap` and shows a toast; doesn't open the player.
  - *Zap receiver and stream* — does both.
- **Zap receiver when changing channel in player** — when on (default), prev/next in the player also tunes the receiver.

### Receiver
- **Box Info** — see [§13](#13-box-info).
- **Receiver settings** *(new in 1.0.6)* — opens the Receiver Settings console. See [§16](#16-receiver-settings).

### Receiver Plugins
- **EPG Import** — appears only when the EPGImport plugin is detected on the receiver. See [§14](#14-epg-import-plugin).

### Background timer notifications
The app polls the timer list every 15 minutes. When a timer transitions to *recording* you get a notification: "Recording started: <title>". On Android 13+ grant the *Notifications* permission when prompted.

## 13. Box Info

Settings → Receiver → **Box Info**.

Displays the receiver's hardware, image, tuner, network and storage details as an ordered key/value list. Calls `api/about` and falls back to `api/deviceinfo` if not available. An empty-state message appears when neither endpoint is supported.

## 14. EPG Import plugin

Settings → Receiver Plugins → **EPG Import** (only visible if the plugin is installed on the receiver).

The app probes several known base paths used by different OpenWebif builds (`epgimport`, `api/epgimport`, `epgimport/plugin`, `plugin/epgimport`) and validates the response body content, so detection works across forks. The first working base is cached for the session.

Inside the screen:

- **Status** — current EPGImport status as reported by the plugin.
- **Source list** — every configured EPG source with a checkbox. Tick / untick to enable or disable individual sources.
- **Save enabled sources** — writes the current selection back to the receiver.
- **Run Import Now** — triggers an EPG import.
- **Refresh** — reloads the source list and status.

## 15. Bouquet Editor *(new in 1.0.5)*

Manage your receiver's bouquets directly from the phone — create, rename, delete bouquets and add, remove or reorder channels.

Access: Settings → **Edit bouquets**.

### Two operating modes

A banner at the top tells you which mode is active:

- **Server mode (green)** — the Enigma2 *BouquetEditor* plugin is installed on the receiver. Every change is pushed to the box and visible to all clients.
- **Local-only mode (amber)** — the plugin isn't installed. Reorder/remove still work, but only on this phone (stored as a local override).

### Main screen

- Lists every user and provider bouquet with its channel count.
- **+ New** *(server mode only)* — create a bouquet. A dialog asks for the name and TV / Radio.
- **Refresh** — reload from the receiver.

For each bouquet:

- **Edit** — open the channel editor (see below). Available in both modes.
- **Rename** *(server mode, user bouquets only)* — rename the bouquet on the receiver.
- **Delete** *(server mode, user bouquets only)* — confirm, then remove from the receiver. Any local override stored for that bouquet is also cleared.

### Channel editor

Open a bouquet to manage its channels:

- **Long-press a row** to drag-reorder.
- **▲ / ▼** buttons step a channel up or down by one position.
- **✕** removes a channel from the bouquet.
- **+ Add channel** opens a filterable picker that lists every channel from every bouquet, skipping ones already in the target bouquet.

In **server mode** every change is sent to the receiver immediately.
In **local mode** changes are saved as an override on this phone and applied client-side whenever this bouquet is loaded.

### Conflict dialog

If you have local edits stored for a bouquet and the BouquetEditor plugin later becomes available, opening the bouquet shows a dialog with three choices:

- **Discard local edits** — drop the override and use what's on the receiver.
- **Keep as a local layer** — leave the override in place; the receiver bouquet is untouched.
- **Apply to receiver** — push the local order/removals up to the receiver, then clear the override.

### Endpoints used (server mode)

- `/bouqueteditor/api/getservices`
- `/bouqueteditor/web/addbouquet`, `renameservice`, `removebouquet`
- `/bouqueteditor/web/addservicetobouquet`, `removeservice`, `moveservice`

## 16. Receiver Settings *(new in 1.0.6)*

A full read+write console for the receiver-side configuration that OpenWebif exposes. Reachable from **Settings → Receiver settings**.

On first entry the app probes the receiver once. Sub-screens whose underlying APIs aren't supported are disabled with *Not available on this receiver.*

### Sub-screens

**Power**
- Shows current state (awake / standby).
- Action buttons: *Toggle standby*, *Enter standby*, *Wake up*, *Reboot receiver*, *Restart GUI (Enigma2)*.
- Sleep timer: enable on/off, time in minutes (15 / 30 / 45 / 60 / 90 / 120 / 180), action when time is up (standby / shutdown).

**Audio & Volume**
- Volume slider 0–100.
- Mute switch.

**Recording**
- Default save location (picker built from the known locations on the receiver).
- List of all known recording paths.
- *Add location…* — type a directory; the app calls `addlocation` with `createFolder=1`.
- Tap any listed path to remove it (confirmation dialog).

**Tuner / Signal**
- Read-only live tuner status: type, tuner number, SNR (dB), BER, signal level (AGC).
- Tap the row to refresh.

**Parental control** *(read-only in this release)*
- Shows whether parental control is configured, the protection type, whether the setup PIN is set, and a count of protected services.
- Lists the names of all currently protected services.

**Wake-on-LAN setup** *(receiver-side)*
- *WOL enabled on receiver* switch.
- *Wake from standby (vs deep)* switch.
- *Wake location / interface* — usually a network interface name (e.g. `eth0`).
- This is the configuration *on the box itself* — it is independent of the *outgoing* Wake-on-LAN feature in the app (see [§17](#17-wake-on-lan)).

**Transcoding**
- Dynamic list — one row per setting reported by the transcoding plugin (resolution, bitrate, framerate, audio codec, …). Edit a value to push it back.
- Empty when the plugin isn't installed (the row is disabled in that case).

**OpenWebif Web UI**
- Six toggles for the Web UI's own behaviour:
  - Show picons
  - Channel picon in lists
  - Show channel details
  - Responsive design
  - MovieDB lookups
  - Show all packages

**All settings (advanced)**
- Generic browser of the receiver's full `config.*` tree. The first screen lists every section the receiver reports; tap one to open its items.
- Each item is rendered by type:
  - Bool → switch
  - Choice → list of options
  - Password → masked text field
  - Directory / Text / Int / Float / Slider → text field
- Every change is saved immediately via `api/saveconfig`.
- Use this for anything not covered by a dedicated sub-screen above. Edits here can affect any part of the receiver — be careful.

### Save behaviour

- Saves run in the background; the UI shows *Saved.* on success or *Receiver error: <message>* on failure.
- Empty `2xx` responses are treated as success (some OpenWebif builds return no body).
- If a sub-screen still shows old values after a save, pop back and reopen it — the screen reloads on entry.

## 17. Wake-on-LAN

Sends a magic packet over UDP to wake a receiver in deep standby.

Requirements:
- WoL enabled in the receiver's network settings.
- MAC address entered in the device profile.
- Tablet and receiver on the same LAN subnet (WoL does not pass through routers by default).

How to use: Channel screen → *Switch Device* → tap the WoL (power) icon next to the device. Wait 30–60 seconds, then tap the device name to connect.

## 18. Troubleshooting

**"Connection failed" / empty channel list**
- Verify IP and port in Settings.
- Tablet and receiver on the same Wi-Fi.
- Test `http://<receiver-ip>/api/info` in a browser.
- If OpenWebif requires auth, enter the username/password in Settings.

**Unauthorised / 401**
- Wrong username / password in the device profile, or OpenWebif auth misconfigured on the receiver.

**Video won't play / black screen**
- Confirm the receiver is actually tuned to that channel.
- Encrypted channels need the correct CAM on the receiver.
- Port 8001 (stream) must not be firewalled.

**Bouquet Editor stuck in local-only (amber) mode**
- Install the BouquetEditor plugin on the receiver (`enigma2-plugin-extensions-bouqueteditor`) and restart Enigma2.
- The app re-probes every time you open the editor, so just go back and reopen.

**Bouquet Editor "Receiver error"**
- Some OpenWebif builds reject a rename/move on a provider bouquet. Use a user-created bouquet instead.
- A 404 on `/bouqueteditor/...` means the plugin isn't fully installed.

**EPG Import not appearing in Settings**
- Confirm the plugin is installed and the OpenWebif plugin endpoints respond. The app probes multiple base paths but a custom proxy or rewrite rule on the receiver can still hide it.

**Box Info empty**
- The receiver's OpenWebif build doesn't expose either `api/about` or `api/deviceinfo`. Update OpenWebif if possible.

**Picons missing** — Picons must be installed on the receiver (typically `/usr/share/enigma2/picon/`).

**No timer notifications on Android 13+** — Grant the *Notifications* permission and disable battery optimisation for the app.

**App shows old data** — Pull down on any list to refresh.

**Receiver Settings sub-screen disabled ("Not available on this receiver.")**
- The receiver doesn't expose the API behind that screen. Typical causes:
  - *Transcoding* — the transcoding plugin isn't installed.
  - *Parental* — parental control was never configured on the box.
  - *All settings (advanced)* — the OpenWebif build doesn't ship `api/config` / `api/config/<section>` (mostly older forks).
  - *WOL setup* — the OpenWebif build doesn't expose `api/getwolsetup`.
- Install / configure the relevant feature on the receiver, then go back and reopen Receiver Settings — capabilities are re-probed on every entry.

**Receiver Settings save fails ("Receiver error: …")**
- Some `config.*` paths are protected or the value is rejected by the underlying Enigma2 setting (e.g. wrong type or out of range). The toast shows the receiver's own message verbatim.

## 22. What's new in 1.1.0 � Receiver admin

The in-app **Receiver settings** area gains a new **System** category and the parental control screen becomes editable.

### Parental control (now editable)

- **Set / change setup PIN** � open Receiver settings ? Parental control ? `Set / change setup PIN`. Enter the current PIN (leave blank if none was set) plus the new PIN twice.
- **Protect a service** � tap `Protect a service` and paste the service reference (the `1:0:1:...` string). Long-press a row in the Channels screen if you need to copy one.
- **Unprotect** � tap a row in the protected services list to confirm and remove parental protection.
- **App-side PIN gate** � at the bottom of the Parental screen, tap `Set app PIN` to require a numeric PIN every time the screen is opened on this device. The PIN is hashed (SHA-256) and stored only locally � it does not affect the receiver. Use `Clear app PIN` to disable the gate.

### System ? Storage & mounts

Read-only listing of the receiver's mountpoints with total / used / free space when reported, plus a SMART information dump for the attached disks. Mount, unmount and format actions are deliberately not exposed in this release.

### System ? System log

Fetches the receiver's recent log via OpenWebif. Type in the filter field at the top to narrow lines by substring (case-insensitive). Tap **Share log** to send the visible text to any sharing target � email, messaging app, file save, etc.

### System ? Plugin manager

Lists the plugins installed on the receiver. Tap **Install plugin** to enter a package name (e.g. `enigma2-plugin-extensions-openwebif`) and install it. Tap any installed plugin to remove it after a confirmation. A warning reminds you that removing core plugins can break the receiver.

### System ? Network info

Shows the receiver's network interfaces with IP, netmask, gateway and MAC where reported. Tap **Copy to clipboard** to grab the full block as text.

### Notes

- Mount/unmount, disk format and a dedicated channel-scan launcher are deferred � endpoint behaviour varies too much across receiver images to ship safely yet.
- All new endpoints fail gracefully � if your receiver image does not expose one, you will see an empty placeholder or a brief error toast and the rest of the app keeps working.

## 23. What's new in 1.1.1 � EPG quality

Three additions to the EPG screens, plus an offline survival aid.

### Refresh EPG

The EPG screen toolbar now has a **Refresh** button next to Search. Tap it to ask the receiver to refresh its EPG (uses the EPGImport plugin endpoint when available, falls back to per-channel refresh otherwise). A toast confirms whether the refresh request was accepted, and the grid reloads automatically.

### Per-channel EPG export

Long-press a channel in the Channels screen ? **Export EPG**. The channel's full EPG window is written to your Downloads folder as both XMLTV and JSON:

- `epg_<channel>_<timestamp>.xml` � XMLTV format, parses with standard `tv_grab_*` tools
- `epg_<channel>_<timestamp>.json` � raw event list

No storage permissions are required (Android 10+ uses `MediaStore`).

### Offline EPG cache

Every successful EPG fetch is snapshotted locally. If a later fetch fails (receiver unreachable, network down, OpenWebif busy), the EPG screen falls back to the last good snapshot and shows a yellow banner `Showing cached EPG (N min old)`. The banner disappears as soon as a fresh fetch succeeds.

### Notes

- The cache lives in `epg_cache` SharedPreferences (one snapshot per bouquet) � no extra database. Clearing app data wipes it.
- MHW2 EPGImport-source toggling was on the original plan but is bundled with the future EPGImport-source picker; the underlying API plumbing landed here.

## 24. What's new in 1.2.0 - External players

You can now hand any channel or recording off to a separate video app instead of the built-in player. This is the recommended way to get Enigma2 streams onto a TV, since most installed players (Kodi, VLC, MX) speak MPEG-TS natively and have their own Chromecast / DLNA / AirPlay paths.

### Settings -> Playback -> Player

- Built-in player (default) - existing behaviour, PiP and EPG OSD intact.
- External player - every channel tap and recording tap launches your video app.
- Ask every time - Android shows the open-with chooser on every launch.

### Settings -> Playback -> Preferred external player

When in External mode, pin a default app so you skip the chooser. The list auto-detects VLC, MX Player, MX Pro, and Kodi (18-20). Pick 'Show chooser each time' to keep the picker active. Pick 'Clear preferred player' to undo.

### How streams are routed

The app sends a standard ACTION_VIEW intent with the OpenWebif stream URL and a sensible MIME type (video/mp2t for live, application/vnd.apple.mpegurl for HLS, video/mp4 etc. for known extensions). VLC/Kodi also receive a 'title' / 'forcename' extra so the on-screen title is correct.

### Why no Chromecast button this release

Chromecast's default media receiver does not play MPEG-TS, so without a custom receiver app the Cast button would fail for nearly every user. Routing through Kodi (which has its own Cast support) is the working alternative today. A real Cast SDK integration may follow once a transcoding-aware receiver is available.

### Notes

- If no external player is installed and External mode is selected, the app silently falls back to the built-in player.
- Schedule playback, favourites, and recording playback all honour the preference.
- The internal player still handles the EPG OSD, zap-on-nav, PiP, and 'auto-resume', so leave it on Built-in if you rely on those features.

## 25. What's new in 1.3.0 - Multi-room and backup

Two features for users who run multiple Enigma2 boxes or set the app up across multiple devices.

### Zap on another receiver

Long-press any channel -> 'Zap on...'. The menu lists every other configured device profile (the entry only appears when you have more than one). Picking a receiver tunes that box without touching the active one. Useful for tuning the bedroom box from the couch, multi-room sports, or staging channels in another room before walking over.

### Profile export / import

Settings -> Backup -> Export device profiles writes every configured receiver to Downloads/enigma2android_profiles_<timestamp>.json. Passwords are stripped by default - tick 'Include passwords (less secure)' to make a fully self-contained backup.

Settings -> Backup -> Import device profiles opens the system file picker. Profiles with the same id are updated in-place; passwords kept by the import file are merged in, but a missing password NEVER silently wipes your existing one.

The JSON format is human-readable so you can hand-edit before re-importing (bulk rename, IP adjustments, etc.).

### Notes

- The new RemoteReceiverApi plumbing also supports OSD messages and could host a 'record on...' action; both are queued for a follow-up release.
- Picon manager, theme picker, and receiver-config backup were on the v1.3.0 longlist but are deferred (file upload to receiver, theme regression surface, image-variant config paths).

## 26. What's new in 1.3.1 - Multi-room polish

Finishes wiring the v1.3.0 multi-room plumbing into the two screens that still had single-receiver versions of the feature.

### Wake-on-LAN picker

The Wake button on the channel toolbar now pops a picker when more than one configured receiver has a MAC address. Pick the box you want to wake and the magic packet is sent. With a single MAC-equipped profile the old one-tap behaviour is preserved.

### Send message picker

The Send message dialog now shows a 'Send to' spinner at the top when you have more than one device profile. Picking a non-active receiver routes the message via the v1.3.0 RemoteReceiverApi so your active receiver/playback is undisturbed. Single-profile setups see no change.

### Notes

- WOL only lists profiles with a non-blank MAC. Set the MAC in the device profile editor to enable wake for that box.
- Picon manager, theme picker, and receiver-config backup remain deferred.

## 27. What's new in 1.3.2 - Reminder actions

EPG reminder notifications now carry two action buttons.

### Watch now

Tap 'Watch now' on the reminder notification and the built-in player launches directly on the channel - no need to open the app and find the bouquet. Uses the active receiver's host/port/HTTPS settings.

### Snooze 5 min

Tap 'Snooze 5 min' to dismiss the current notification and re-fire it five minutes later. The snoozed reminder is re-persisted so it survives reboots, and uses the same inexact alarm path as v1.0.8 (no SCHEDULE_EXACT_ALARM permission required).

### Notes

- Plain notification body tap still auto-cancels as before.
- If you ignore both actions and the notification times out, the reminder is removed from the persistent store (existing behaviour).
